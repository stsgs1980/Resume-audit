# SPEC-ui: интерфейс и экспорт

Часть спецификации Resume Audit.
См. также: [SPEC.md](SPEC.md), [SPEC-verification.md](SPEC-verification.md).

## 1. Три режима

| Режим | Назначение          | Когда открывается            |
| ----- | ------------------- | ---------------------------- |
| Обзор | «Где я, что дальше» | Первый запуск, возврат       |
| Этапы | Работа с данными    | 90% времени                  |
| Ревью | Работа с документом | После генерации, верификация |

Дашборд не редактирует. Он показывает и ведёт. Всё редактирование —
в этапах и в ревью.

## 2. Правило переключения

Приложение ведёт пользователя:

- первый запуск -> Обзор;
- есть незавершённый этап -> открыть его;
- все этапы 1–6 закрыты, есть версия -> Ревью;
- все замечания разобраны -> Обзор с разблокированным экспортом;
- после экспорта -> Обзор.

## 3. Экран Обзор

- прогресс по 8 этапам одной строкой;
- блок «Требует внимания» с одной главной кнопкой «Продолжить»;
- сводка: файлов, фактов, расхождений;
- список версий со статусами (`verified`, `stale`, `pending`);
- кнопка «Экспорт» (заблокирована или разблокирована).

## 4. Экраны этапов

| Этап         | Содержимое                                         |
| ------------ | -------------------------------------------------- |
| 1. Файлы     | Выбор папки, таблица с типом, кодировкой, статусом |
| 2. Факты     | Редактор facts.json, вычисляемые поля read-only    |
| 3. Аудит     | Расхождения, блок-лист, прогнозные, плейсхолдеры   |
| 4. Вопросы   | Очередь open_questions с полями evidence           |
| 5. Роли      | Оценки 0–10 с обоснованиями                        |
| 6. ATS       | Ключевые слова по трём категориям                  |
| 7. Генерация | Три версии, кнопки экспорта                        |
| 8. Отчёт     | Итоговая сводка, известные ограничения             |

## 5. Режим Ревью

Резюме слева, рекомендации справа.

### 5.1. Двусторонняя связь

- наведение на рекомендацию подсвечивает место в резюме;
- наведение на число подсвечивает рекомендацию;
- клик по рекомендации — скролл к месту и раскрытие деталей;
- клик по числу — карточка доказательства.

Без двусторонней связи получается «два несвязанных списка»,
и пользователь теряет контекст.

### 5.2. Счётчик и фильтры

Счётчик «N из M» — прогресс разбора. Прогресс-бар заполняется по мере
закрытия рекомендаций.

Фильтры: Все, Ошибки, Предупреждения, Числа, Навыки.

### 5.3. Карточки рекомендаций

Каждая карточка содержит:

- серьёзность (ошибка / предупреждение);
- тип (`unsupported_number`, `missing_hedge`, `contradiction`,
  `unsupported_skill`, `forbidden_word`, `skill_no_usage`,
  `needs_evidence`, `rounding`);
- заголовок;
- детали;
- цитату из резюме;
- действия.

Действия: «Удалить», «Переформулировать», «Внести в факты»,
«Допустимое отклонение» (с обязательной причиной).

Применённое действие закрывает рекомендацию. Карточка становится
серой, зачёркнутой, уходит вниз списка.

## 6. Кликабельность чисел

- В `facts.json` клик по числу показывает источник: файл, цитату,
  поля карточки доказательства.
- В сгенерированном резюме клик по числу открывает запись в `facts.json`
  по `fact_id`.

Без `fact_id` в схеме генерации кликабельность нереализуема.

## 7. Цвета статусов

- `confirmed` — зелёный;
- `needs_evidence` — жёлтый;
- `remove` — красный;
- предупреждение — жёлтое;
- ошибка блокировки — красное.

## 8. Экспорт

Для каждой версии:

- `.md` — для чтения и архива;
- `.txt` — чистый текст для вставки в форму hh.ru;
- копирование блоками — отдельная кнопка для каждого поля формы:
  тайтл, специализация, контакты, «Обо мне», каждое место работы
  по отдельности, навыки, языки;
- JSON — для отладки и версионирования.

Копирование в буфер без переформатирования.

Кнопка «Экспорт» заблокирована при неразрешённых расхождениях
или статусе `stale`.

## 9. Пометка в документе

Каждый сгенерированный документ несёт пометку:

> Сгенерировано из facts_hash=..., prompt_version=..., model_id=...
> Действительно на <audit_date>.

## 10. Безопасность отображения

Все тексты из файлов резюме — пользовательский ввод.

- Обязательное экранирование HTML при выводе в UI.
- Внутри `style`/`script` вырезается до извлечения текста.
- Экранирование при рендере — независимая защита.

## 11. Персистентность состояния

При возврате приложение показывает «Продолжить с этапа N» — последний
этап в статусе `completed`.

Статусы и хэши в `stage-state.json`.

## 12. Баннер конфиденциальности

При первом запуске — баннер:

> Резюме — персональные данные. Тексты утверждений и черновики резюме
> передаются в opencode server и далее в провайдера модели.

Логирование содержимого резюме — только с явного согласия.
