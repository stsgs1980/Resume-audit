# SPEC-meta: расширяемость, версионирование, ограничения

Часть спецификации Resume Audit.
См. также: [SPEC.md](SPEC.md), [SPEC-facts.md](SPEC-facts.md).

## 1. Конфиг как данные

Всё, что может меняться без переписывания логики, — в `config/`.

```text
config/
  roles/
    sales.json
    salesops.json
    aipo.json
  skills-rules.json
  forbidden-words.json
  thresholds.json
  exceptions.json
  prompts/
    extraction.v1.md
    roles.v1.md
    generation.sales.v1.md
    generation.salesops.v1.md
    generation.aipo.v1.md
    verification.v1.md
  schemas/
```

Новая роль — новый файл в `roles/` плюс новый промт генерации.
Код не меняется.

Новое правило — новый файл в `config/` плюс тест. Код не меняется.

## 2. Версионирование артефактов

Каждый артефакт несёт:

```json
{
  "schema_version": 1,
  "prompt_version": "generation.sales.v1",
  "model_id": "opencode/big-pickle",
  "model_params": { "temperature": 0.2, "seed": null },
  "run_id": "run_2026-10-09_001",
  "created_at": "2026-10-09T12:00:00Z",
  "facts_hash": "sha256:...",
  "meta_hash": "sha256:..."
}
```

Это даёт:

- воспроизводимость для детерминированного ядра;
- трассировку: что и когда сгенерировано;
- миграции: когда `schema_version` растёт;
- отладку: что именно поменялось.

## 3. Что хэшируется

`facts_hash` — только контент фактов: `jobs`, `education`, `languages`,
`confirmed_skills`, `portfolio_projects`.

`meta_hash` — содержимое `meta`: `audit_date`, `candidate_name`,
`geography`, `targets`.

Разделение важно: смена `audit_date` меняет стаж (он вычисляется
относительно даты), но не меняет сами факты. Это две разные причины
для инвалидации.

## 4. Миграции схем

`migrations/` — скрипты перехода между `schema_version`.

При загрузке старого `facts.json` приложение предлагает миграцию,
не ломается молча.

## 5. Reproducibility contract

Детерминированное ядро воспроизводимо: одинаковый вход -> одинаковый
выход.

LLM-слой не гарантирует битовую воспроизводимость. Записываются
`prompt_version`, `model_id`, `model_params`. При смене любого из них
результат может отличаться.

Это не баг, это свойство. Явно указать в README.

## 6. Наблюдаемость

- `run_id` во всех логах и артефактах;
- `stage-state.json` — по записи на документ, не глобально;
- `model-responses.log` с ротацией, без содержимого резюме;
- `audit-trail.json` — кто, что, когда менял в `facts.json`.

## 7. Расширение

### 7.1. Новая целевая роль

1. Создать `config/roles/<role>.json` с ATS-ключевыми словами.
2. Создать `config/prompts/generation.<role>.v1.md`.
3. Добавить роль в `meta.targets` в `facts.json`.
4. Обновить `share_of_applications`, чтобы сумма осталась в 0.99–1.01.

Код не меняется.

### 7.2. Новое правило аудита

1. Добавить функцию в модуль ядра.
2. Добавить тест.
3. Если правило параметризуемое — вынести пороги в `thresholds.json`.

Код меняется минимально.

### 7.3. Новый формат файла

1. Добавить парсер в модуль чтения.
2. Добавить строку в таблицу обработки ошибок.
3. Добавить тест на битый файл.

## 8. Ограничения

1. Приложение **не знает** алгоритмов ранжирования hh.ru и не делает вид,
   что знает.
2. Качество текстовых оценок зависит от модели. Space Bunny Free —
   модель бесплатного уровня: хуже работает с длинным контекстом
   и числовыми рассуждениями. Вся арифметика и проверки — в коде.
   На подключении более сильной модели вырастет только качество оценок,
   не расчёты.
3. **Конфиденциальность.** Резюме — персональные данные. Тексты
   утверждений и черновики резюме передаются в opencode server и далее
   в провайдера модели. `model-responses.log` не должен попадать
   в систему контроля версий.
4. Тексты вакансий не обязательны. Без них ключевые слова строятся
   на гипотезе и помечаются в отчёте.
5. Приложение не проверяет факты через работодателей и не может этого
   делать. Оно находит внутренние противоречия и требует карточек
   доказательств.
6. Ни одно сгенерированное резюме не публикуется без верификации
   и заполненных карточек доказательств.
7. Вся конструкция опирается на то, что `facts.json` собран честно.
   Если человек подтвердил неверный факт, система этого не поймает.
8. Транзитивная уязвимость в `braces` (dev-only, stylelint) —
   см. `SECURITY.md`.
