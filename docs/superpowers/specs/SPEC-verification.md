# SPEC-verification: верификация и граф зависимостей

Часть спецификации Resume Audit.
См. также: [SPEC.md](SPEC.md), [SPEC-pipeline.md](SPEC-pipeline.md).

## 1. Назначение

Без верификации приложение небезопасно: модель обязательно что-то вставит.
Проверка идёт в два слоя. Слой 1 (код) детерминирован и не может быть
обойдён. Слой 2 (LLM) — дополнение.

## 2. Слой 1 — код

1. Все числа извлекаются из готового текста. Каждое обязано:

- присутствовать в `facts.json` в нормализованном виде;
- принадлежать целевой роли по полю `roles`.

1. Числа-исключения, не требующие сверки:

- годы в датах;
- номера телефонов;
- номера в маркированных списках;
- возраст;
- номера версий.
  Список исключений — явный и редактируемый, не разбросан по коду.

1. Навыки из поля навыков обязаны быть в `confirmed_skills` для этой роли
   и отсутствовать в `skillRules`.
1. Запрещённые слова — во всём тексте, включая опыт и «Обо мне».
1. Плейсхолдеры — во всём тексте.
1. Заголовок — без слэша, соответствует целевой роли.
1. `needs_evidence` с `hedge_required: true` обязан сопровождаться
   нейтрально-деловым маркером атрибуции из белого списка в том же
   абзаце. Нет маркера — блокировка.
   - Для косвенных метрик: «по данным годового замера компании»,
     «по данным управленческого учёта», «в составе кросс-функциональной
     команды».
   - Для пет-проектов и R&D: «разработал прототип», «пилотная версия»,
     «проектирование в роли бизнес-заказчика».
   - Анти-паттерны оправданий запрещены в тексте резюме
     (см. `config/forbidden-words.json`): «не заявляю»,
     «не выдаю за результат», «чего у меня нет», «эффекта нет».
1. Штатный выход Этапа 7 — артефакт `interview-defense.md`. Собирается
   из карточек `data/evidence/<id>.json` (поля: `metric_definition`,
   `formula`, `baseline`, `zone_of_influence`, `confirmed_by`).
   Это боевая карточка защиты цифр на собеседовании.
1. `target_metrics` портфельных проектов не должны появляться в блоке
   результатов.
1. Сумма `share_of_applications` в пределах 0.99–1.01.
1. Обязательные поля hh.ru присутствуют.

Без списка исключений верификатор будет блокировать экспорт на каждом
телефоне. Пользователь отключит проверку — хуже, чем её нет.

## 3. Слой 2 — LLM

Отдельный вызов: дать сгенерированное резюме и `facts.json`, попросить
составить список всех числовых утверждений и сверить каждое с фактами.

Схема ответа:

```json
{
  "checks": [
    {
      "number": "",
      "claim": "",
      "matches_fact": true,
      "fact_id": "",
      "matches_role": true,
      "has_hedge": true,
      "verdict": "ok | unsupported_number | wrong_role | missing_hedge | is_target_metric",
      "comment": ""
    }
  ],
  "unsupported_skills": [],
  "forbidden_words_found": []
}
```

## 4. Правило вывода

Любое расхождение -> красный блок с указанием места и сути. Экспорт
заблокирован.

Пользователь может пометить расхождение как «допустимое отклонение»
с указанием причины — попадает в лог и в финальный отчёт как известное
ограничение.

## 5. Граф зависимостей

```text
  ФАЙЛЫ (вход)              ЯДРО (код)                LLM
  *.md *.txt *.docx         этап 1: чтение            -
  *.pdf *.html              этап 3: даты, стаж,       -
  вакансия                  числа, ATS               -
                            этап 4: вопросы           -
                              <- ЧЕЛОВЕК
                            facts.json
                            ИСТОЧНИК ПРАВДЫ
                            этап 2: claims            LLM (1 вызов)
                            этап 5: роли              LLM (1 вызов)
                            этап 6: ATS               LLM (1 вызов)
                            этап 7: генерация         LLM (3 вызова)
                            этап 8: верификация       LLM (3 вызова)
                            stage-state.json
                            ЭКСПОРТ (fail-closed)
```

## 6. Три правила, которые реализуют неправильно

1. **Инвалидация по-документная.** `stage-state.json` хранит запись
   на каждый документ отдельно. Перегенерация версии 2 трогает только
   запись версии 2. Глобальный флаг `allStale` — ошибка.
2. **Гейт ядра перед LLM.** Пока тесты ядра не зелёные, LLM-этапы
   не запускаются.
3. **Исключения в верификации обязательны.** Без списка исключений
   слой 1 заблокирует экспорт на любом номере телефона.

## 7. Условия блокировки экспорта

Экспорт заблокирован, если:

- документ `stale`;
- есть неразрешённое расхождение верификации;
- `sum(share_of_applications)` не входит в `[0.99, 1.01]`;
- отсутствует обязательное поле hh.ru;
- есть открытые `needs_evidence`;
- `facts.json` не в состоянии `locked`.

## 8. Уровни проверки

Блок-лист навыков работает на входе — до генерации, в этапах 2 и 3.
Верификация работает на выходе и ловит то, что проскочило.

Эти два уровня не дублируют друг друга: первый отсеивает, второй
не даёт пройти.
